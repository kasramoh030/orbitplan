# OrbitPlan — Spatial Planner (Redesigned)

نسخهٔ بازطراحی‌شده و دوزبانهٔ OrbitPlan برای برنامه‌ریزی مطالعه، کار، هدف‌ها و جلسات تمرکز.

## اجرا

### حالت محلی / PWA

برای استفادهٔ محلی و نصب PWA، اپ را با یک وب‌سرور اجرا کنید:

```bash
python3 -m http.server 4174 --bind 0.0.0.0
```

### حساب کاربری و Cloud Sync

برای توسعهٔ محلی، سرور همراه با Node 18 یا بالاتر اجرا می‌شود:

```bash
npm install
export ORBITPLAN_TOKEN_SECRET='a-long-random-development-secret'
node cloud-server.js
# سپس http://localhost:4175 را باز کنید
```

سرور محلی بدون `DATABASE_URL` از storage فایل JSON استفاده می‌کند. برای production، PostgreSQL و Docker Compose آماده شده‌اند:

```bash
cp .env.example .env
# مقادیر secret، دامنه و رمز PostgreSQL را در .env واقعی عوض کنید
docker compose --env-file .env up --build
```

در production باید HTTPS، `DATABASE_URL`، `ORBITPLAN_TOKEN_SECRET` تصادفی، CORS محدودشده و volume پایدار PostgreSQL داشته باشید. مسیر راه‌اندازی OAuth رسمی در `OAUTH_CALENDAR_SETUP_FA.md` مستند شده است.

### Supabase PostgreSQL آماده

پروژهٔ Supabase OrbitPlan در `eu-west-1` ایجاد و migrationهای account/sync/collaboration/activity روی آن اعمال شده‌اند. برای اتصال runtime، از `.env.supabase.example` و `docker-compose.supabase.yml` استفاده کنید؛ راهنمای کامل و محدودیت‌های deployment در `SUPABASE_PRODUCTION_RUNBOOK_FA.md` است. template از session pooler استفاده می‌کند تا در شبکه‌های فاقد IPv6 نیز قابل‌اتصال باشد و با runtime واقعی اعتبارسنجی شده است. هیچ password یا service key در source/ZIP نگهداری نمی‌شود.

### Netlify رایگان برای PWA + API

`netlify.toml` و `netlify/functions/orbitplan.js` آماده‌اند: Netlify PWA را static منتشر می‌کند و `/api/*` را به همان Node API، در قالب serverless function، می‌فرستد. تنظیمات و secretهای لازم در `NETLIFY_DEPLOYMENT_FA.md` ثبت شده‌اند. این مسیر برای prototype/beta رایگان مناسب است؛ WebSocket/realtime و rate limit توزیع‌شده به host یا سرویس مکمل نیاز دارند.

## همکاری پروژه و امنیت نشست

1. در **مرکز داده ← حساب و ابر** وارد همان Cloud endpoint شوید.
2. در **پروژه‌ها**، برای یک پروژهٔ خصوصی «انتشار برای تیم» را بزنید. کد دعوت editor هفت روز اعتبار دارد و در صورت امکان در clipboard کپی می‌شود.
3. عضو دیگر با همان endpoint از «پیوستن با کد» استفاده می‌کند. مالک می‌تواند invite تازه برای editor یا viewer بسازد و هر کد فعال را از همان پنل **لغو** کند؛ viewer فقط دریافت تغییرها را دارد.
4. هر عضو مجاز از **ارسال تغییرها** و **دریافت تغییرها** استفاده می‌کند. ارسال بر پایهٔ revision انجام می‌شود؛ در تعارض، نسخهٔ تیم برای دریافت پیشنهاد می‌شود تا تغییر محلیِ ارسال‌نشده ناخواسته overwrite نشود.
5. بخش **فعالیت‌های تیم** تاریخچهٔ انتشار، پیوستن عضو، ارسال تغییر، ساخت invite و لغو invite را با actor و زمان نمایش می‌دهد.
6. در **مرکز داده ← امنیت** می‌توان گذرواژه را تغییر داد یا نشست‌های دیگر را باطل کرد. هر دو عملیات token-version را افزایش می‌دهند؛ تنها token تازهٔ پاسخ معتبر می‌ماند.

همکاری حاضر عمداً **pull/push دستی** است؛ حضور لحظه‌ای، cursor مشترک، اعلان ایمیلی و merge سه‌طرفه هنوز به سرویس realtime/notification و طراحی حل تعارض کامل نیاز دارند. کد دعوت یک credential است: فقط از کانال مطمئن به اشتراک بگذارید. HTTPS، secret تصادفی و PostgreSQL برای محیط عمومی الزامی‌اند.

> در اولین اجرا، دادهٔ وظایف نسخهٔ قبلی (`orbitplan-tasks`) در صورت وجود به نسخهٔ جدید منتقل می‌شود.
